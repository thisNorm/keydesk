# 설정·백업·복원 작업 결과

담당 범위: `apps/web/src/Settings.tsx`, 새 `apps/web/src/settings-model.ts`, 새 `apps/web/test/settings-model.test.ts`, 이 기록과 설정 전용 `settings-flow.py`. 공용 UI, CSS, 라우터, 서버, HTTP 계약, 의존성, 기존 브라우저 검사는 수정하지 않았다. 기존 dist도 건드리지 않았다.

- 설정을 일반·알림 메일·백업·복원·서버 사용량 설정 탭으로 나눴다. 탭은 `설정 항목` 이름의 tablist, 각 패널은 선택한 탭을 이름으로 쓰는 tabpanel이다. 화살표·Home·End 키로 이동할 수 있다.
- 서버가 전체 Settings를 받는 계약이므로 일반은 시간대, 메일은 SMTP, 서버는 보존일·환율·기준일의 초안만 저장값에 합친다. 다른 섹션의 초안과 SMTP 암호를 함께 보내지 않는다. SMTP 암호는 별도 메모리 상태로 입력받고 저장 응답에서 제거하며 로컬 저장소에 넣지 않는다. 빈 입력은 기존 암호 유지다.
- 백업과 복원은 서로 다른 폼과 소유자 비밀번호·파일 암호 상태를 쓴다. 파일 선택에는 API 요청이 없으며 복원 버튼은 검증된 파일이 있어야 켜진다. 빈 파일, 24MiB 초과 파일, 미지원 형식·KDF·필드·암호화 봉투와 서버가 허용하는 16MiB를 넘는 암호문을 준비 단계에서 거절한다. 읽기 결과의 늦은 반영도 방지한다.
- Windows↔Mac 파일 이동 방법과 백업 암호 보관을 짧게 안내한다. 복원 마지막 확인에는 교체 범위, 합쳐지지 않는다는 점, 현재 소유자 계정 유지, 모든 세션과 클라이언트 키 폐기를 설명한다. 성공 뒤 기존 인증 상태 갱신을 유지한다. 재인증·백업 암호 실패는 기존 API의 현재 로그인 보존 처리를 이용한다.
- 메일 없이도 앱 알림을 쓸 수 있다고 표시한다. 저장된 SMTP 서버와 받는 주소, 미저장 변경 상태를 따로 표시하고 테스트 메일은 저장된 설정으로 보낸다고 안내한다.
- 비밀번호 변경은 새 값과 확인 입력의 일치를 검사한 뒤 기존 API를 호출한다. 성공하면 기존처럼 모든 세션이 종료된다. 시간대 초안이 남아 있으면 먼저 저장하도록 안내해 로그아웃에 따른 유실을 막는다.
- 탭·주 메뉴 이동에서 작성 내용을 유지하거나 버릴 수 있다. 루트가 보내는 cancelable `window` 이벤트 `keydesk:before-navigate`와 `detail.resume`을 사용한다. 작성 중 새로고침·탭 닫기는 beforeunload로 보호하고, 제출·파일 읽기 중에는 내부 이동을 막는다. 민감한 작업을 떠나면 입력한 암호와 복원 파일 상태를 지운다. 테마는 선택적 props를 사용하며 부모가 저장한다.
- 저장 API가 성공한 뒤 부모의 화면 갱신만 실패한 경우 저장 성공과 갱신 실패를 구분한다.

검증:

1. `source /workspace/.keydesk-tools/activate.sh && node --test apps/web/test/settings-model.test.ts`: 기존 동작을 반영한 초기 scaffold에서 8개 assertion 실패를 확인하고 구현 후 8/8 통과했다. 섹션별 병합, 다른 섹션 암호 제외, SMTP 암호 제거, dirty 범위, 파일 크기·형식·암호문 한도를 다룬다.
2. `npm run typecheck --workspace @keydesk/web`: exit 0. 담당 소스의 타입 오류나 보고하지 않은 임시 공유 오류는 없다.
3. `npx prettier --check apps/web/src/Settings.tsx apps/web/src/settings-model.ts apps/web/test/settings-model.test.ts`: 통과.
4. `source /workspace/.keydesk-tools/activate.sh && python .local/ux-2026-11-06/settings-flow.py`: 변경 전 tablist 부재로 실패를 확인했고, 최종 임시 API+Vite+Chromium 실행은 exit 0, page errors 0. 실제 메뉴 초안 취소/버리기·이동, 탭 초안 보호와 Home/End 이동, 일반/서버 독립 저장, 저장된 메일 설정 테스트 요청, 백업 내려받기와 양쪽 암호 분리, 파일 형식 게이트, 파일 선택 시 백업 요청 없음, 잘못된 소유자·백업 암호 뒤 로그인 및 현재 설정 유지, 정상 복원 후 세션 폐기·설정 복원, 비밀번호 불일치 차단·성공 후 새 비밀번호 로그인, 390px 가로 넘침 없음과 비밀 입력의 로컬 저장소 부재를 확인했다. 복원 전후 검사는 백업에 보존일 45일을 담은 뒤 현재를 46일로 바꿔 실패 시 46일 유지·성공 시 45일 복원을 확인한다.

SMTP 테스트 요청은 브라우저 경계에서 응답을 가로채 실제 메일을 보내지 않았다. 나머지 설정·백업·복원·인증 요청은 실제 임시 서버를 사용했다. Linux Chromium 결과이며 Windows·macOS 실기 검증으로 보고하지 않는다. 루트 담당의 최종 전체 테스트·빌드·통합 검증은 별도다. 커밋·push·게시·설치·실제 데이터 수정은 수행하지 않았다.

통합에 쓰는 정확한 이름:

- 탭: `일반`, `알림 메일`, `백업`, `복원`, `서버 사용량 설정`.
- 저장 버튼: `일반 설정 저장`, `메일 설정 저장`, `서버 사용량 설정 저장`.
- 작성 보호: 대화상자 `작성 내용 버리기`, 버튼 `계속 작성` / `버리고 이동`.
- 백업: 입력 `현재 소유자 비밀번호`, `새 백업 파일 암호 (12자 이상)`; 버튼 `암호화 백업 내려받기`.
- 복원: 입력 `복원할 암호화 백업 파일`, `현재 소유자 비밀번호`, `복원할 파일의 백업 암호`; 버튼 `복원 내용 확인`; 대화상자 `현재 데이터를 백업으로 교체`; 마지막 버튼 `전체 복원 실행`.
- 비밀번호: `현재 비밀번호`, `새 비밀번호 (12자 이상)`, `새 비밀번호 확인`; 버튼 `비밀번호 변경`.
