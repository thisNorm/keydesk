# 보관함 폼 담당 결과

범위는 새 `EntryEditor.tsx`, `ImportEntries.tsx`, `RotateCredential.tsx`, `CredentialDateField.tsx`, `editor-model.ts`, `test/editor-model.test.ts`와 이 기록이다. 공용 UI·CSS·서버·계약·의존성·다른 담당 파일을 수정하지 않았다. 설계의 고정 props를 그대로 사용한다.

## 구현

- 등록은 이름·첫 인증값을 앞에 두고 키 이름·만료일을 바로 편집한다. 상태·발급일, 제공사·주소·태그·관리 메모는 접을 수 있다. 모든 기존 메타데이터와 다중 키를 보존한다.
- 신규 등록에 현재 프로젝트를 기본 적용하고 같은 창에서 프로젝트를 만든 뒤 선택한다. 프로젝트 생성 응답 후 목록 갱신만 실패해도 이미 만든 프로젝트를 로컬 화면에 유지해 중복 생성을 유도하지 않는다.
- 키 제거에 확인을 받고 작성 중 닫기·취소는 계속 작성/내용 버리기를 제공한다. 작성 중 `beforeunload`를 보호하며 저장·프로젝트 생성 중 닫기를 막는다. 새 프로젝트 Enter 처리에는 한글 조합 방어가 있다.
- 날짜는 명시적인 연-월-일 텍스트 입력과 한국어 달력을 제공한다. 달력은 방향키·Home/End·Page Up/Down·Escape를 지원한다. 기존 ISO 시각·오프셋은 원문 그대로 보존하며 날짜를 선택할 때 시각을 잃는다는 설명을 보여 준다. 날짜 필드는 자체 연결 라벨을 사용하고 선택적인 외부 id/aria-describedby도 실제 입력에 전달한다.
- 전용 교체는 `/entries`의 최신 항목을 읽고 기대한 credential id/version을 확인한다. 다른 키의 값은 보내지 않으며 다른 키 메타데이터와 최신 항목 메타데이터를 유지한다. 새 발급일·만료일은 빈 값으로 시작한다.
- `.env` 가져오기는 기존 파서를 재사용한다. 잘못된 줄·중복·빈 값을 설명하고 고정 마스크로 미리보기를 표시한다. 기존 항목에 추가할 때도 최신 항목을 읽고 `/entries/import` 단일 원자적 요청으로 보낸다. 파일 읽기 중 새 붙여넣기/다른 파일 선택이 생기면 늦은 파일 결과를 버린다.
- 항목/교체/가져오기 저장 응답을 받은 뒤에는 공통 `finishSaved`가 목록 갱신 실패를 별도로 알리고 폼을 닫는다. 목록 오류가 저장 실패나 재저장으로 이어지지 않는다.

## 결정과 남은 검증

- Ruling: 최신 항목 단건 GET이 없는 현재 공개 API를 유지하기 위해 교체와 기존 항목 가져오기 직전에 GET `/entries`로 최신 메타데이터를 구한다. 비용은 전체 목록을 한 번 더 읽는 것이다.
- Ruling: 날짜만 입력하는 브라우저 기본 위젯의 운영체제별 순서 차이를 피하기 위해 연-월-일 텍스트와 의존성 없는 한국어 달력을 사용했다. ISO 입력은 변환하지 않는다. 직접 날짜를 선택하면 명시적으로 날짜 전용 값이 된다.
- Ruling: 독립 작업의 파일 소유권을 지키기 위해 전체 제품 빌드·전체 시험·실제 Chromium 통합은 부모 담당이 수행한다. 폼 담당은 범위 시험과 웹 타입 검사만 실행한다.
- 서버에서 GET과 PUT 사이를 원자적으로 비교하는 계약은 추가하지 않았으므로 그 사이에 생기는 동시 변경까지 막지는 못한다. 이는 명세의 명시된 경계다.
- 실제 브라우저에서 포커스 복귀·작성 취소 복귀·저장 중 닫기·한국어 달력 키보드·프로젝트 생성·저장 후 목록 실패 흐름은 부모의 통합 검사가 필요하다. Windows/macOS 실기 동작을 검증했다고 주장하지 않는다.
