# Keydesk 보관함 UI·UX 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Independent forms and settings use frozen interfaces and separate file ownership.

**Goal:** 일반 사용자의 등록·검색·복사·만료 확인·교체·백업 흐름을 실제 앱에서 개선한다.

**Architecture:** 현재 React 앱과 HTTP 계약을 유지하고 상단 메뉴·전체 폭 목록·행 아래 상세를 적용한다. 등록·가져오기·교체 폼을 분리하고 설정 폼도 작업별로 분리한다. 백엔드와 인증·암호화 저장 구조는 변경하지 않는다.

**Tech Stack:** React 19, TypeScript, 기존 npm workspaces와 Node 26, node:test와 Python Playwright.

**Spec:** `docs/superpowers/specs/2026-11-06-vault-ux-design.md`

## Global Constraints

- 사용자 문구는 한국어, 날짜 기준은 설정 시간대이며 기본 Asia/Seoul이다.
- 사이드바·상시 오른쪽 상세·선택 색 띠·카드형 컨테이너를 제거한다.
- 사용자 입력·실제 비밀값을 로컬 저장소·URL·로그·캡처에 넣지 않는다.
- UI 의존성·외부 제공사 호출·DB 변경·환경 게시·원격 push를 추가하지 않는다.
- 모든 검증은 임시 데이터에 수행한다. 기존 15,484개 파일 삭제와 독립 앱 변경은 사전 작업이며 이번 검토 범위와 구분한다.
- 현재 클라우드 체크아웃의 사전 스냅샷은 `.local/ux-2026-11-06/before`, 진행 기록은 `.local/ux-2026-11-06/progress.md`다. 사용자가 실행 판단을 맡겼으므로 추가 승인 질문 없이 수행한다.

## Review Focus

- 한 항목에 만료·예정·미등록·중지 키가 섞여 있어도 각 필터와 요약이 실제 대상 키를 가리켜야 한다.
- 이전 버전과 늦게 끝나는 복사 요청이 현재 값이나 닫힌 화면으로 다시 나타나면 안 된다.
- 기존 ISO 날짜의 오프셋과 다른 키 메타데이터는 교체·일반 수정으로 손실되면 안 된다.
- 저장 응답 후 목록 조회만 실패했을 때 항목이 중복 생성되면 안 된다.
- 작성 중 취소, 닫힌 선택 필드의 검증, 좁은 창과 한글 조합에서 데이터가 뜻하지 않게 저장·유실되면 안 된다.

## Task 1: 폼과 교체 흐름

**Files:** 새 `apps/web/src/vault/{EntryEditor,ImportEntries,RotateCredential,CredentialDateField}.tsx`, `vault/editor-model.ts`, `apps/web/test/editor-model.test.ts`.

**Interfaces:** 설계 문서의 폼 props를 그대로 사용한다. 부모는 저장 ID로 목록을 다시 읽고 해당 행을 연다. `/entries`, `/entries/import`, `/projects`와 현재 인증 모듈을 사용한다. 공용 소스·CSS·의존성을 수정하지 않는다.

- [ ] 다른 키 값 유지·오프셋 보존·대상 키만 교체하는 순수 로직 검사를 작성하고 실패를 확인한다.
- [ ] 이름·값 중심 등록, 프로젝트 기본 선택과 생성, 선택 정보 접기, 키 제거 확인·작성 내용 보호를 구현한다.
- [ ] 한국식 날짜 입력과 날짜 선택, 정확한 시각 원본 보존을 구현한다.
- [ ] 최신 항목을 읽어 대상 버전을 확인하는 전용 교체 창을 구현한다.
- [ ] 원자적 `.env` 가져오기와 마스킹, 저장 후 갱신 실패의 경고 처리를 구현한다.
- [ ] 담당 테스트와 TypeScript 검사 결과를 보고한다. 커밋·푸시하지 않는다.

## Task 2: 설정과 백업·복원

**Files:** `apps/web/src/Settings.tsx`, 설정 전용 검증 파일.

**Interfaces:** 기존 props와 선택적인 테마 props를 유지하며 `GET/PUT /settings`, `/settings/smtp/test`, `/backups`, `/backups/restore`, `/auth/password`를 사용한다. 공용 소스·CSS·의존성은 수정하지 않는다.

- [ ] 백업과 복원이 별도 폼·암호 상태를 갖는 사용자 흐름 검사를 먼저 작성한다.
- [ ] 일반·알림 메일·백업·복원·서버 설정을 분리하고 작업에 맞는 입력만 보인다.
- [ ] 메일 선택 설정, 저장 후 테스트, 보호된 암호 입력과 복원 재인증을 유지한다.
- [ ] 계정 비밀번호 변경에 확인 입력을 제공하고 성공 후 세션 갱신 동작을 유지한다.
- [ ] 담당 검사와 TypeScript 결과를 보고한다. 커밋·푸시하지 않는다.

## Task 3: 전체 폭 보관함과 탐색

**Files:** `main.tsx`, `Vault.tsx`, 새 `Secret.tsx`, `helpers.ts`, `ui.tsx`, `style.css`, `helpers.test.ts`, `browser.py`, `DESIGN.md`.

**Interfaces:** Task 1 폼을 소비한다. Task 2 설정을 상단 설정 메뉴에 연결한다. 기존 백엔드 형식과 `api/copyText/setAuth` 동작을 유지한다.

- [ ] 사전 전체 검사를 실행하고 프런트엔드 스냅샷을 보존한다.
- [ ] 혼합 키의 필터·요약·정렬·검색 회귀 검사와 과거 버전 닫기 회귀 검사를 먼저 실행해 실패를 확인한다.
- [ ] 키별 필터와 날짜 비교·검색, 안전한 보기 설정 복원을 구현한다.
- [ ] 상단 메뉴·서버 보조 메뉴·한 항목의 행 아래 펼침을 실제 앱에 적용한다.
- [ ] 값 숨김·복사 실패·과거 값 표시·현재 버전 복귀를 유지·보완한다.
- [ ] 프로젝트에서 항목 보기, 알림에서 항목 찾기, 빈 상태와 조건 초기화, 저장 행 자동 선택을 연결한다.
- [ ] 공용 폼의 검증과 닫기·한글 조합 처리, 밝은/어두운 평면 스타일, 좁은 화면을 적용한다.
- [ ] `npm test`, `npm run build`, 실제 브라우저 흐름을 통과시킨다.

## 사전 인터페이스 점검

- Task 1 → Task 3: 폼 props와 저장 ID 전달은 설계의 선언으로 고정했다. UI·CSS는 루트만 수정한다.
- Task 2 → Task 3: 테마 props는 선택 인수라 기존 호출도 유지된다. 서버 설정 저장은 현재 HTTP 형식을 사용한다.
- 모든 담당 → `Modal/Field/Form/Confirm`: 기존 인수는 유지한다. 루트의 선택적인 확인 버튼 문구 확장만 허용한다.
- 검토 기준은 사전 스냅샷이다. 기존 전체 재구축의 미커밋 변경을 이번 UI 작업으로 오인하지 않는다.
