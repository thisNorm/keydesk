# Keydesk 독립 구현 설계

Keydesk는 Norm이 자신의 API 키를 보관하고, 이후 프로젝트의 API 호출을 중계하면서 사용량과 비용을 확인하는 개인용 웹 앱이다. 이 문서는 기존 제품의 소스와 실행 환경을 새 구현으로 교체하는 범위와 완료 기준을 정한다. 현재 상태는 구현 전 검토안이다.

## 목표와 전환 방식

사용자는 화면의 이름 변경이나 메뉴 숨김보다 소스, 저장 구조, 실행 환경, 문서까지 독립된 Keydesk를 원한다. 보관함의 사용 편의가 첫 번째 우선순위다. 게이트웨이도 전체 구현 범위에 포함하며, 맥미니를 구입하기 전에도 개발과 로컬 검증을 진행한다. 상시 운영 시점만 장비 준비에 맞춘다.

사용자는 한국에서 혼자 사용하며 Windows PC와 맥북을 함께 사용한다. 화면, 입력 안내, 오류와 복구 안내, 메일, 설치·운영 문서는 한국어로 작성한다. 제공사 고유명, API 식별자와 실행에 필요한 코드 문법은 정확한 값을 유지한다. 다국어 선택 화면과 번역 관리 시스템은 만들지 않는다.

### 검토한 접근

| 접근                                              | 결과와 비용                                                                    | 판단                               |
| ------------------------------------------------- | ------------------------------------------------------------------------------ | ---------------------------------- |
| 기존 엔진을 유지하며 이름과 메뉴 수정             | 빠르게 화면을 바꿀 수 있지만 기존 API, 저장 구조, 공용 UI, 배포 이미지가 남음  | 완전한 독립이라는 요구에 맞지 않음 |
| 기존 코드를 축소하며 내부 이름과 구조 변경        | 기존 기능을 활용할 수 있지만 광범위한 의존 관계와 마이그레이션을 유지해야 함   | 사용하지 않는 기능까지 관리하게 됨 |
| 필요한 기능을 새로 구현하고 현재 저장소의 앱 교체 | 인증, 저장, 백업을 다시 검증해야 하지만 제품과 운영 범위를 직접 통제할 수 있음 | 사용자가 요청한 전환 방향으로 채택 |

### 재사용과 보존 범위

현재 보관함의 등록 항목, 명시적인 키 보기와 복사, 한국어 문구, 화면 밀도와 색상 취향을 요구사항으로 참고한다. 기존 화면, CSS, 공용 컴포넌트, 인증 코드, 암호화 코드, 데이터베이스 마이그레이션, 문서 및 이미지를 새 앱으로 복사하지 않는다. 공개 라이브러리는 각각의 원래 라이선스를 준수해 새 의존성으로 설치한다.

현재 체크아웃은 커밋 `172e8d0979`이며 작업 트리가 깨끗하다. 대화에 등장한 이후의 알림, 백업, 문구 변경 작업은 이 체크아웃에 없다. 다른 브랜치나 PC의 변경을 여기에 이미 반영된 작업으로 간주하지 않는다. 보존할 실제 보관 데이터의 유무는 확인되지 않았다.

전환의 제안 기본값은 새 보관함으로 시작하는 것이다. 기존 데이터베이스를 자동으로 열거나 변환하지 않는다. 이전할 실제 데이터가 발견되면 원본을 보존하고, 중립적인 내보내기 파일을 통한 별도 이전 절차로 범위를 추가한다. 기존 서버를 새 앱의 필수 의존성으로 남기지 않는다.

제품 교체는 같은 저장소에서 진행한다. 구현 전에 전체 커밋과 로컬 파일을 복구할 수 있는 보존 지점을 확인한다. 기존 `.env`, 데이터 디렉터리, Docker 볼륨, 사용자 파일을 삭제하거나 기존 데이터베이스를 초기화하지 않는다. 새 앱은 별도 이름과 데이터 경로를 사용한다. Git 과거 기록은 유지하며 강제 푸시나 기록 재작성은 수행하지 않는다.

### 제거 완료 기준

새 앱이 아래의 기능 검증을 통과하면 기존 앱의 서버, 프런트엔드, 공용 UI, 기업용 모듈, CLI 통합, Go 부분 구현, WASM 소스, 배포 이미지, 차트, CI 및 문서를 현재 파일 트리에서 제거한다. 기존 자산의 저작권 고지를 지우고 새 코드로 취급하는 방식은 사용하지 않는다. 기존 자산을 재사용할 필요가 생기면 먼저 의존 관계와 고지 의무를 검토한다.

최종 앱의 소스, 구성, 환경변수, 데이터베이스, 화면, 메일, 로그, 문서, CI, 컨테이너 이름과 이미지에는 기존 제품의 이름, URL, 라이선스 검사 또는 실행 의존성을 남기지 않는다. 이전 커밋과 별도 보존한 원본에는 그 당시의 고지를 유지한다. 새 루트 문서와 에이전트 지침은 실제 Keydesk 구조에 맞게 교체한다. 새 앱의 라이선스는 제안 기본값으로 MIT와 `Copyright 2026 thisNorm`을 사용한다.

## 앱 구조와 보관함

다음 기술 선택은 구현자가 제안한 기본값이며 사용자가 특정 기술을 지정한 것은 아니다. React와 TypeScript로 화면을 만들고 Vite로 빌드한다. 서버는 Node 26의 Fastify를 사용한다. 저장소는 npm workspaces로 구성한다. 제품 소스는 `apps/web`, `apps/server`, 공유 입력 형식은 `packages/contracts`로 분리한다.

서버 한 프로세스가 정적 UI와 관리 API를 제공한다. 데이터베이스는 SQLite WAL 모드로 두고 짧은 트랜잭션을 사용한다. Redis와 외부 계정 서비스는 필수 의존성에서 제외한다. 한 명이 한 인스턴스를 운영하는 범위에 맞춘 선택이며 여러 서버로 분산하는 기능은 이번 범위에 없다. 외부 API 호출, 파일 입출력 또는 메일 발송 중 데이터베이스 트랜잭션을 유지하지 않는다.

### 첫 실행과 로그인

첫 실행은 로컬 접근만 허용한다. 영구 데이터 디렉터리에 일회용 초기 설정 토큰을 비공개 파일로 생성하고, 이를 확인한 사용자만 소유자 계정을 만들 수 있다. 로그인 화면에서 첫 계정을 아무나 선점할 수 없게 한다. 이후 공개 회원가입, 조직, 팀, 초대 및 역할 선택 화면은 제공하지 않는다.

비밀번호는 Node의 scrypt로 단방향 해시한다. 해시 매개변수는 서버에서 고정하고 검증하며 요청마다 임의로 바꿀 수 없게 한다. 로그인 실패에는 속도 제한을 적용한다. 세션은 난수 토큰을 사용하고 서버에는 해시만 보관한다. 쿠키에는 HttpOnly와 SameSite 속성을 설정하며 HTTPS 운영에서는 Secure를 사용한다. 변경 요청은 Origin 검사와 CSRF 방어를 적용한다. 로그아웃, 비밀번호 변경, 복원은 필요한 세션을 폐기한다. 비밀번호 재설정은 서버의 로컬 관리 명령으로 수행한다.

### 보관 데이터와 암호화

보관 항목에는 이름, 제공사, 용도, 사이트·발급 콘솔·문서·API 주소, 소유자 메모, 태그, 요금제 메모를 저장한다. 사용 프로젝트는 독립된 목록으로 관리하고 항목과 다대다로 연결한다. 자유 문자열 프로젝트 목록을 다시 만들지 않는다.

한 항목에 여러 인증값을 등록할 수 있다. 각 인증값에는 고유 식별자, 이름, 상태, 발급일, 만료일을 따로 두어 서로 다른 만료일을 표현한다. 상태는 사용 중, 중지, 폐기를 구분한다. 키 교체는 새 버전으로 기록하며 변경 시각과 사유를 남긴다. 이전 키 값은 암호화된 버전 기록에 보관하고 명시적인 조회만 허용한다.

키 값과 버전 기록은 AES-256-GCM으로 암호화한다. 매번 새 nonce를 사용하고 항목·인증값·버전을 추가 인증 데이터에 연결한다. 루트 암호화 키는 데이터베이스 밖의 영구 비공개 파일 또는 명시적인 런타임 비밀값으로 관리한다. 기존 데이터가 있으면 누락된 루트 키를 자동으로 새로 만들지 않는다. 초기 버전에서는 루트 키의 자동 교체를 제공하지 않는다.

목록 API는 인증값, 복호화된 과거 버전, 키 일부를 반환하지 않는다. 보기와 복사는 별도 인증된 API로 처리하고 응답에는 캐시 금지 헤더를 설정한다. 화면은 일정 시간이 지나거나 잠기면 표시한 값을 지운다. 인증값을 로컬 스토리지, URL, 분석 이벤트, 오류 추적, 애플리케이션 로그에 저장하지 않는다. 애플리케이션 암호화는 서버 관리자나 이미 침해된 실행 프로세스로부터 키를 숨기는 기능으로 설명하지 않는다.

### 보관함 사용 흐름

로그인하면 보관함이 첫 화면으로 열린다. 제공사, 용도, 사용 프로젝트, 상태와 만료 상태를 먼저 읽을 수 있게 하고 기본 목록에는 키를 표시하지 않는다. 검색, 프로젝트·제공사·태그·상태·만료 필터와 정렬을 제공한다. 요금제·한도 메모는 실제 측정값과 구분해 표시한다.

등록과 편집은 같은 폼을 사용한다. 입력 중인 변경을 취소할 때 확인하고, 프로젝트가 없으면 등록 흐름 안에서 생성한다. 삭제와 복원은 대상과 결과를 표시한 뒤 확인받는다. 저장 성공 후 알림 등록 같은 후속 작업이 실패하면 저장 성공과 후속 실패를 구분해 중복 등록을 막는다. 한국어와 키보드 조작을 지원하며 작은 화면에서도 조작부를 사용할 수 있게 한다.

### 개인 화면과 한국 사용 환경

기존 기업용 콘솔의 탐색 구조를 새 앱에 가져오지 않는다. 주요 탐색은 보관함, 프로젝트, 사용량, 게이트웨이, 설정으로 구성하고 각 기능이 완성된 단계에서 실제로 작동하는 메뉴만 노출한다. 조직 선택, 팀 관리, 서비스 광고와 사용하지 않는 제품 메뉴는 제공하지 않는다. 첫 화면에는 전체 키, 만료 임박, 만료됨, 상태 확인이 필요한 항목을 표시하고 선택하면 해당 목록으로 연결한다.

디자인의 제안 기본값은 흑연·네이비 표면, 청록 강조색, 얇은 경계선과 정돈된 정보 밀도다. Keydesk와 Norm의 정체성을 헤더와 앱 아이콘에 적용한다. 항목 이름과 용도는 한글을 읽기 편한 크기와 줄 간격으로 두고, 키·주소·숫자에만 고정폭 글꼴을 사용한다. 운영체제의 한글 글꼴을 활용하고 외부 폰트 로딩을 필수로 만들지 않는다. 색상 외에 텍스트와 아이콘으로 상태를 구분하고 키보드 초점과 대비를 확보한다.

사용자는 생성형 AI가 만든 전형적인 대시보드처럼 보이는 디자인을 피하고 싶다고 요청했다. 수정 시안은 큰 숫자 요약 카드, 홍보성 제목과 부제, 반복 알림 배너, 제공사별 장식 아이콘, 과도한 배지와 중첩 카드를 제거했다. 목록의 열, 짧은 만료 필터, 간결한 상세 정보와 낮은 채도의 강조색으로 사용성을 표현한다. 화면을 밋밋하게 만드는 것만을 목표로 삼지 않고 항목 간 정렬, 한글 가독성, 선택과 편집의 명확함을 확인한다.

사용자가 제공한 [GDWEB 참고 목록](https://www.gdweb.co.kr/sub/list.asp?Txt_fgbn=7)은 디자인 참고 후보이며, 아직 실제 사례를 열람하지 못했다. 현재 수정 시안에 해당 사이트를 참고했다고 설명하지 않는다. 최종 화면은 사용자가 수정 시안을 검토한 뒤 확정한다.

Windows의 일반 모니터, 맥북의 작은 화면과 Retina 화면을 모두 고려한다. 넓은 화면에서는 목록과 상세를 함께 읽게 하고 좁은 화면에서는 상세 패널로 전환한다. 브라우저 확대, 긴 한글 이름과 긴 URL에서도 가로 스크롤 없이 주요 조작을 사용할 수 있게 한다. 추가·검색·필터·보기·복사는 화면에서 바로 찾을 수 있게 하고 익숙한 동작을 불필요한 확인창으로 막지 않는다. 삭제·비밀값 내보내기·복원에는 영향 범위를 설명한다.

날짜는 한국어 형식과 Asia/Seoul 시간대를 기본으로 표시한다. 상대 만료 문구에는 실제 날짜를 함께 제공하고, 운영체제의 시간대가 달라도 만료 계산과 일일 한도의 날짜 경계를 바꾸지 않는다. 날짜만 입력한 키는 지정일의 한국 시간 마지막 시각까지 유효한 것으로 계산한다. 명시적인 시각이 있는 제공사 만료값은 해당 시각을 보존하고 한국 시간으로 표시한다.

통계는 한국어 숫자 구분과 원화 표시를 지원한다. 제공사 단가와 관측 비용의 원래 통화는 보존한다. 원화 환산은 사용자가 설정한 환율과 기준일을 함께 표시한 추정값으로 제공하며, 실제 결제액이나 자동 조회한 최신 환율로 표현하지 않는다.

공통 동작은 버튼으로 모두 제공하고 단축키는 보조 수단으로 사용한다. Windows는 Ctrl, macOS는 Command 표기를 구분한다. 한글 입력기의 조합 중 Enter가 저장이나 검색을 실행하지 않게 한다. 클립보드 권한 거부에는 수동 복사 경로를 제공하며, 복사 성공으로 보고한 뒤 실제로 복사되지 않는 상태를 만들지 않는다. 앱이 운영체제 클립보드의 모든 복사본을 지울 수 있다고 설명하지 않는다.

기기 간 사용은 브라우저에서 동일한 서버에 접속하는 방식으로 제공한다. Windows와 맥북에서 각각 독립 실행하면 데이터가 자동 동기화되는 것으로 표현하지 않는다. 상시 서버가 생기기 전에는 암호화 백업으로 옮길 수 있고, 이후에는 같은 서버의 보관함을 사용한다.

### 알림, 가져오기와 백업

만료 임박·만료됨 알림을 앱 안에서 먼저 제공한다. 기본 시간대는 Asia/Seoul이며 변경할 수 있다. 만료일은 해당 시간대의 날짜로 해석한다. 기본 알림 시점은 30일 전, 7일 전, 당일이며 인증값 버전·시점별 중복을 방지한다. 중지와 폐기된 키는 예정 알림을 취소한다. 앱이 꺼져 있던 동안의 만료 상태는 다음 시작 때 계산하며 꺼져 있는 동안 발송했다고 표시하지 않는다.

SMTP는 선택 사항으로 제공한다. 설정 화면에서 연결을 검사하고 테스트 메일을 보낼 수 있게 한다. 설정이 없으면 앱 알림은 계속 동작하고 메일 미설정 상태를 표시한다. SMTP 비밀번호는 암호화해 저장한다. 메일에는 항목 이름, 제공사와 만료일만 포함한다.

`.env` 가져오기는 내용을 실행하지 않고 입력값으로만 파싱한다. 저장 전에 변수 이름, 연결할 프로젝트, 새 항목 또는 기존 항목 연결을 확인할 수 있게 한다. 원문과 인증값은 로그에 남기지 않는다. 잘못된 형식과 중복은 해당 입력에 표시한다.

사용자는 설정 화면에서 암호를 지정해 암호화 백업 파일을 내려받고 같은 화면에서 복원한다. 백업은 인증값의 모든 버전과 관리 메타데이터를 일관된 시점으로 포함하고, 서버 루트 키와 독립된 백업 암호로 암호화한다. 복원할 때 키 값은 대상 서버의 루트 키로 다시 암호화한다. 파일 형식 버전, 키 유도 방식, salt, nonce를 명시하고 무결성을 검증한다. 파일 크기와 키 유도 매개변수에 상한을 둔다.

백업에는 세션, 초기 설정 토큰, 소유자 비밀번호 해시를 넣지 않는다. 새 서버에서는 계정을 먼저 만들고, 기존 서버에서는 소유자를 재인증한 뒤 복원한다. 복원은 보관 데이터, 프로젝트, 설정 및 이후 단계의 게이트웨이 설정·사용 기록을 교체하는 전체 복원이며 병합 가져오기와 구분한다. 대상 서버 계정은 유지한다. 복원 후 기존 세션과 클라이언트 키를 폐기하며 클라이언트 키는 새로 발급해야 한다.

복원은 비운영 후보 데이터베이스에 검증하고, 작업 전 현재 상태를 자동 보존한 다음 실제 데이터베이스를 원자적으로 교체한다. 실패하면 기존 데이터를 계속 사용할 수 있어야 한다. 수동 백업 외에 같은 파일 형식을 생성하는 예약 백업 명령과 보존 개수 설정을 제공한다. 서버 디스크 안에만 보관한 백업을 외부 재해 복구 백업으로 설명하지 않는다.

## 게이트웨이와 운영

게이트웨이는 보관함과 같은 앱 안의 별도 모듈로 구현한다. 관리 API에 사용하는 사용자 세션과 프로젝트가 사용하는 클라이언트 키를 구분한다. 중계 기능의 개발과 로컬 테스트는 맥미니 구입을 기다리지 않는다.

### 중계와 클라이언트 키

프로젝트마다 클라이언트 키를 발급하고 최초 한 번만 전체 값을 표시한다. 서버에는 검증용 해시, 이름, 범위, 발급일, 만료일, 마지막 사용 시각과 폐기 상태만 저장한다. 프로젝트에 허용한 경로와 보관 인증값만 사용할 수 있으며 다른 키 조회, 관리 API 접근, 목적지 변경은 허용하지 않는다.

소유자는 중계 경로마다 목적지 HTTPS 주소, 경로·메서드 범위와 주입할 인증 헤더를 설정한다. 일반 REST 중계와 OpenAI·Anthropic의 사용량 해석기를 제공한다. 중계 경로의 별칭은 식별용이며 비밀값으로 취급하지 않는다. 클라이언트 인증 헤더를 검증한 뒤 제공사 인증값으로 교체하고, 쿠키와 hop-by-hop 헤더처럼 전달하면 안 되는 헤더는 제거한다. 쿼리 매개변수에 키를 넣는 방식은 초기 범위에서 제외한다.

사용량 해석기의 초기 보장 범위는 OpenAI의 Responses와 Chat Completions, Anthropic의 Messages에 대한 JSON·SSE 응답이다. 각 API의 스트림 종료, 토큰 사용량, 오류와 취소를 로컬 모의 제공사로 검증한다. 그 밖의 제공사는 일반 REST 중계를 지원하며 사용량을 해석하지 못하면 미확인으로 기록한다. 실제 사용자 키를 이용한 외부 호출은 별도로 구분한다.

목적지는 관리자가 등록한 주소로 고정하며 요청 본문이나 경로로 임의 호스트를 지정할 수 없게 한다. 주소 결합, DNS 해석과 실제 연결을 검증해 루프백, 메타데이터 주소 및 사설 네트워크 접근을 막는다. 리다이렉트는 자동 추적하지 않는다. 내부 제공사가 필요하면 관리자가 특정 목적지를 명시적으로 허용하는 설정을 별도로 사용한다. 검증 로직은 새 구현으로 작성하고 악의적인 주소 입력과 DNS 응답 변경을 테스트한다.

요청과 응답은 크기·연결 시간·유휴 시간 상한을 적용한다. SSE는 전체 버퍼링 없이 전달하고 연결 종료와 취소를 제공사 요청에 전파한다. 사용량 수집은 제한된 크기의 이벤트 파서로 처리하며, 클라이언트가 느려지면 스트림의 흐름을 제어한다. 제공사 오류, 취소 및 부분 스트림을 성공으로 기록하지 않는다. 중복 과금 위험이 있는 요청을 자동 재시도하지 않는다.

### 사용량, 한도와 비용

호출 기록에는 시각, 프로젝트, 클라이언트 키 식별자, 중계 경로, 인증값 버전 식별자, 모델, 상태, 지연 시간, 사용량 출처를 저장한다. 제공사 키, 클라이언트 키, 요청·응답 본문 및 인증 헤더는 기록하지 않는다. 기록 보존 기본값은 30일이며 사용자가 바꿀 수 있게 한다.

게이트웨이를 통과한 호출만 측정했다고 표시한다. 제공사에서 직접 사용한 호출과 계정 전체 잔액을 측정한 것으로 표현하지 않는다. 일반 REST는 호출 수를 측정하고 제공사가 사용량을 반환하는 경우에만 토큰을 기록한다. 스트림에서 사용량을 얻지 못하면 미확인으로 표시하며 0으로 합산하지 않는다.

일일 호출 수 제한은 전송 전에 원자적으로 예약해 동시 요청에도 한도를 지킨다. 공급자에 실제 전송한 시도는 오류 응답과 취소를 포함해 호출 수에 포함하고, 전송 전에 거부한 요청은 제외한다. 날짜 경계는 설정된 시간대를 사용한다. 토큰·비용의 강제 상한은 제공사와 요청에서 상한을 예약할 수 있는 경우에만 제공하며, 정확한 사전 상한이 없으면 사용량 알림 한도로 표시한다. 사용량 미확인 시 강제 상한 모드에서는 다음 호출을 차단하고 관리자가 해결할 수 있게 한다.

비용은 소유자가 입력한 모델별 단가, 통화, 적용 시작일과 실제 관측 사용량으로 추정한다. 입력·출력·캐시 토큰의 단위를 구분하며 계산에는 정수 최소 화폐 단위 또는 고정소수점을 사용한다. 단가 변경이 과거 기록을 다시 계산하지 않도록 호출 당시 단가 버전을 연결한다. 다른 통화는 임의 환산해 합치지 않는다. 제공사 청구액과 같은 값이라고 설명하지 않는다.

### 배포와 유지보수

Docker Compose 한 서비스로 앱을 실행하고 데이터와 루트 키는 영구 볼륨에 보관한다. 기본 바인딩은 루프백이다. macOS에서 Docker Desktop을 사용하는 절차와 Linux 서버 절차를 문서화한다. 이미지 빌드는 AMD64와 ARM64를 지원하며 실제로 실행 검증한 아키텍처와 빌드만 검증한 아키텍처를 구분해 보고한다.

Windows에서는 Docker Desktop의 Linux 컨테이너와 WSL2 구성을 지원하고 PowerShell에서 실행할 수 있게 한다. macOS에서는 Intel과 Apple Silicon을 고려하며 맥북의 개발·보관용 실행과 맥미니의 상시 운영을 구분해 안내한다. OS나 장비별 절차를 Linux용 셸 명령 한 종류로 대신하지 않는다. 데스크톱 전용 패키징 없이 브라우저 UI를 공통으로 사용한다.

맥미니 배포 시 관리 화면은 로컬 또는 VPN 안에 두고, 외부 프로젝트가 필요로 하는 게이트웨이 경로만 TLS 프록시를 통해 공개한다. 클라이언트 키 검증, 속도 제한과 로그 비밀값 제거는 공개 전부터 구현한다. 외부 업데이트 확인, 분석 수집, 기존 서비스 접속 및 라이선스 서버 호출은 넣지 않는다.

시작, 중지, 상태 확인, 업데이트 전 백업과 복구를 짧은 명령으로 제공한다. Windows에서는 실행 파일을 찾도록 구성하고, 현재 관리 스크립트의 고정 Docker Desktop 경로와 컨텍스트를 그대로 복사하지 않는다. 스키마 변경은 버전별 마이그레이션으로 수행하며 이전 스키마에서 시작하는 앱은 무리하게 실행하지 않고 복원·업데이트 경로를 안내한다.

관리 명령은 Node로 작성해 PowerShell과 macOS의 zsh에서 같은 npm 명령을 사용할 수 있게 한다. 경로는 플랫폼 API로 구성하고, 파일 선택·백업·복원은 한글과 공백이 들어간 경로를 지원한다. `.env` 가져오기는 CRLF와 LF, UTF-8 BOM을 처리한다. 파일을 사용자 화면에서 다룰 때 서버의 절대 경로를 입력하도록 요구하지 않는다.

SQLite 파일과 백업 파일에서 평문 키가 노출되지 않는지 검사한다. 로그인·복호화 실패, 복원 실패, 게이트웨이 권한과 동시 한도를 검증하는 테스트를 둔다. 외부 제공사 자격 증명을 요구하는 테스트는 기본 검사와 분리하고, 실제로 호출하지 않은 외부 연동을 검증 완료로 보고하지 않는다.

화면은 한글 입력기 조합, Ctrl·Command 표기, 브라우저 확대, 키보드 탐색, 좁은 화면의 조작부와 클립보드 거부를 확인한다. 서버·도구의 자동 검사는 Windows와 macOS에서 실행하고 한국어·공백 경로와 줄바꿈 차이를 포함한다. 현재 Linux 환경에서 확인한 결과를 Windows·macOS 실제 실행 결과로 보고하지 않는다.

기존 클라우드 환경의 설치 스크립트, 시작 절차와 실행 중인 서비스는 새 앱 검증 후 교체한다. 준비된 파일과 실제로 실행한 검사, 설정 초안 저장, 게시, 새 환경 복원을 각각 구분해 보고한다.

### 구현자에게 맡기는 결정

세부 파일 구성, 지원 라이브러리의 정확한 버전, SQL 테이블·인덱스 이름, API의 세부 응답 형식과 테스트 파일 배치는 구현 계획에서 정한다. 선택한 버전의 보안 유지 상태와 Node 26·ARM64 호환성을 확인한다. SQLite 드라이버는 Node 26 내장 드라이버를 우선 검토하되 안정성과 백업 API의 제약이 있으면 이유를 기록하고 지원되는 드라이버를 선택한다.

현재 구현을 시작하기 전 필요한 확인은 이 설계의 범위와 제안 기본값에 대한 사용자 검토다. 이후 실제 보존 데이터나 다른 브랜치 작업이 발견되면 이를 덮어쓰지 않고 전환 계획에 반영한다.
