# Keydesk 보관함 사용성 개선 설계

사용자가 UI·UX 최적화와 일반 사용자 관점의 보완을 직접 맡겼다. 이미 비교한 상단 메뉴·행 아래 펼침 구조를 기본으로 실행하며, 세부 선택은 구현자의 판단이다. 기존 초안의 재적용이나 환경 게시는 하지 않는다. 현재 코드를 개선하는 작업이다.

## 목표와 사용 흐름

상시 서버가 없는 현재는 키를 등록하고 사용처·유효기간을 확인하며 필요한 값을 복사하는 도구다. 등록 → 검색·프로젝트 필터 → 키 복사 → 만료 확인 → 교체 → 백업이 매끄러워야 한다. 서버 중계와 사용량 기능은 유지하면서 보조 메뉴로 정리한다.

기존 React·Fastify·SQLite와 HTTP 계약을 유지한다. 신규 UI 의존성·자동 제공사 호출·계정 연동·청구 API·서버 배포를 추가하지 않는다. 실제 사용자 데이터와 루트 키를 변경하지 않으며 시험 데이터는 임시 저장소만 쓴다.

## 화면 방향

- 고정 사이드바, 오른쪽 상시 상세, 색 상태 띠, 카드 컨테이너를 제거한다.
- 상단에 보관함·프로젝트·알림·서버 메뉴를 두고 설정·잠금을 오른쪽에 둔다. 서버는 게이트웨이·사용량으로 이어진다.
- 기본은 흰색·검정·회색, 만료·삭제 같은 의미 있는 상태만 색과 글자로 표시한다. 어두운 화면도 같은 평면 구조를 유지한다. 외부 폰트·장식 아이콘을 추가하지 않는다.
- 목록 전체 폭을 쓰고 선택 항목의 인증값을 해당 행 아래에 펼친다. 한 번에 한 항목만 열며 목록을 접거나 조건에서 사라지면 조회한 값도 지운다.
- 프로젝트 선택, 만료 필터, 검색과 정렬은 목록 위에 둔다. 필터가 걸린 빈 목록에는 조건 초기화를 제공한다. 처음 빈 보관함에는 직접 추가·가져오기 동작을 제공한다.
- 이름·프로젝트·키 개수·만료일을 정렬하고, 긴 이름·여러 프로젝트·정확한 만료 시각·작은 창을 고려한다. 창 장식을 흉내 내지 않는다.

## 필터와 검색

기존 필터가 가장 빠른 만료일 하나만 검사하는 문제를 고친다. 사용 중인 각 키를 기준으로 30일 이내·만료됨·만료일 미등록을 판별한다. 한 항목에 지난 키·곧 만료될 키·미등록 키가 같이 있어도 각각의 필터에 나타난다. 필터에 맞는 키의 날짜를 목록 요약에 표시한다. 모든 키가 중지·폐기된 항목은 전체 목록에 남고 사용 중인 키가 없다고 표시한다.

만료일순·이름순·최근 수정순을 제공한다. 날짜가 없으면 만료일순의 뒤쪽이며, 정확한 시각과 날짜만 있는 값은 설정 시간대에서 비교한다. 한국어 조합·프로젝트 이름·키 이름·태그·메모도 검색할 수 있게 한다. 검색어와 비밀값은 저장하지 않는다. 정렬·필터 같은 열거형 보기 설정만 로컬에 저장할 수 있다.

## 등록·수정·교체

등록은 이름과 첫 인증값을 중심으로 한다. 용도·프로젝트·키 이름·만료일은 가까이 두고 제공사·각종 주소·요금제·소유자·태그·긴 메모는 선택 영역으로 둔다. 현재 프로젝트 필터를 신규 항목에 기본 적용한다. 다중 키·상태·키별 발급일/만료일과 기존 모든 메타데이터를 편집할 수 있어야 한다.

프로젝트는 같은 창에서 만들고 선택한다. 인증값 제거는 확인을 받고, 입력한 창을 닫을 때 작성 내용이 있으면 버릴지 묻는다. 저장 중에는 창이 닫혀 중복 요청이 발생하지 않게 한다. 날짜만 입력할 때는 연·월·일 순서가 명확해야 하고, 기존 ISO 시각과 오프셋은 수정하지 않는 한 그대로 보존한다.

각 키 옆에 교체 동작을 제공한다. 교체 창은 새 값·발급일·만료일·상태에 집중한다. 새 키의 만료일을 추측하지 않는다. 최신 항목 메타데이터로 교체 요청을 만들고 다른 키의 값과 메타데이터를 보존한다. 다른 화면에서 이미 교체된 키는 새 상태를 확인하도록 안내한다. 서버의 원자적 동시성 제어를 새로 보장하는 작업은 아니다.

서버 저장이 성공한 뒤 목록 갱신이 실패하면 저장 실패처럼 표현하거나 다시 저장하도록 하지 않는다. 저장한 항목을 선택하고 목록을 다시 읽을 수 있게 한다. `.env` 가져오기는 계속 미리 확인하고 원자적으로 처리하며, 잘못된 줄과 중복·빈 값을 설명하고 값은 미리보기에서 마스킹한다.

## 인증값 조회와 교체 이력

복사는 각 키 옆에서 한 번에 수행하며 값을 목록에 미리 가져오지 않는다. 조회는 20초·창 이탈·항목 접기·잠금 시 지운다. 복사 권한이 없으면 직접 선택하는 경로를 제공한다. 늦게 끝나는 요청이 접힌 항목이나 이전 버전 값을 다시 표시하면 안 된다.

이전 버전을 선택했을 때 과거 값임을 명확히 표시하고, 교체 기록을 닫으면 현재 버전으로 되돌린다. 과거 값을 현재 값으로 오해하고 복사하는 흐름을 없앤다.

## 설정·프로젝트·알림

설정은 일반·알림 메일·백업·복원·서버 사용량 설정을 구분해 관련 작업만 보여준다. 백업 만들기와 파일 복원은 별도 폼과 암호 상태를 사용한다. Windows↔Mac 이동에 암호화 백업을 쓰는 방법과 복원 시 교체되는 범위를 한국어로 안내한다. 복원에는 소유자 재인증과 최종 확인을 유지한다. SMTP 없이 앱 알림을 쓸 수 있음을 알린다. 테스트 메일은 저장된 설정으로 보낸다는 사실이 명확해야 한다.

프로젝트 목록에서 연결된 보관 항목으로 이동할 수 있게 한다. 알림에서 해당 항목으로 이동하면 남아 있는 필터 때문에 보이지 않는 일이 없어야 한다. 연결된 항목과 키가 없는 경우 다음 동작을 제공한다.

## 구현 경계와 인터페이스

- 루트: `main.tsx`, `Vault.tsx`, `Secret.tsx`, `helpers.ts`, `ui.tsx`, `style.css`, 브라우저 통합 검사, 가이드·문서.
- 폼 담당: 새 `vault/EntryEditor.tsx`, `vault/ImportEntries.tsx`, `vault/RotateCredential.tsx`, `vault/CredentialDateField.tsx`, `vault/editor-model.ts`, `test/editor-model.test.ts`.
- 설정 담당: `Settings.tsx`와 설정 범위의 새 브라우저 검사 파일. 다른 담당의 소스와 의존성을 수정하지 않는다.
- `EntryEditor`: `{entry?:Entry, projects:Project[], onProjects:()=>Promise<void>, onClose:()=>void, onSaved:(id:string)=>Promise<void>, defaultProjectId?:string, notify?:(message:string)=>void, zone?:string}`.
- `ImportEntries`: `{entries:Entry[], projects:Project[], onClose:()=>void, onSaved:(id?:string)=>Promise<void>, notify:(message:string)=>void}`.
- `RotateCredential`: `{entry:Entry, credential:Credential, zone:string, onClose:()=>void, onSaved:(id:string)=>Promise<void>, notify:(message:string)=>void}`.
- `SettingsPage`: 기존 `{notify,onAuth,onSaved}`와 선택 인수 `{theme?:'system'|'light'|'dark',onThemeChange?:(value:'system'|'light'|'dark')=>void}`. 서버 HTTP 형식은 바꾸지 않는다.
- 공용 `Modal/Field/Form`의 기존 인수는 유지한다. `Confirm`에 선택적 `confirmLabel`, `cancelLabel`을 추가할 수 있다. 새 폼 클래스는 기존 `form-grid/field/inline/check/form-actions/key-editor`와 `editor-section/field-help/settings-tabs/settings-section/backup-actions`를 사용한다.

## 검증

의미 있는 회귀 검사는 혼합 상태 키의 필터, ISO 시각·오프셋 보존, 교체 시 다른 키 유지, 기존 버전 조회 후 현재 버전 복귀, 작성 내용 취소·복귀, 저장 성공 후 갱신 실패, 백업과 복원 분리, 복사 거절, 한글 IME와 Ctrl/Command, 좁은 창을 다룬다. 순수 스타일의 테스트를 추가하지 않는다.

기존 전체 테스트와 빌드·타입·포맷 검사, 임시 데이터로 실행하는 실제 Chromium 흐름을 통과시킨다. 최종 화면은 임시 시험 데이터로만 캡처한다. Windows·macOS 실기 확인이나 실제 외부 SMTP·제공사 호출을 검증했다고 표현하지 않는다. UI 변경 범위를 현재 파일의 사전 스냅샷과 비교해 독립 검토하고 중요한 문제를 수정한다. 원격 push·환경 게시를 수행하지 않는다.
